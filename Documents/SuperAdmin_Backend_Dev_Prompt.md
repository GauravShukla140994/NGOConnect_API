## 1. Project Stack & Architecture (Non-Negotiable)

- ASP.NET Core 8, C#, MySQL 8.0
- Architecture: **Controller → Interface → DAL (inherits `BaseDal`) → Stored Procedure**
- No EF Core — ADO.NET + Stored Procedures only, via `IDbProvider` (`MySqlDbProvider`)
- API standard: `ApiResponse<T>` (`IsSuccess`, `Message`, `Data`, `ErrorCode`)
- All lookups via `LookupTypes` + `LookupValues` (never hardcoded enums)
- All write SPs return `SELECT IsSuccess, Message [, EntityId]`
- `DynamicRow` for display/read queries; typed request models for writes only
- `DynamicRow.Get<T>()` returns `T?` even for value types — always `?? default` before use in a non-nullable context (real bug already hit once in `SuperAdminDal.LoginAsync`, fixed there — watch for it in every new method)
- JWT: same signing key/issuer/audience as the existing pipeline. Super Admin gets its own role claim, `ClaimTypes.Role = "SUPER_ADMIN"`, generated by a private method inside `SuperAdminDal` (not via `AuthDal`)

### Step 1 — New SP: full org status history (needed for the drawer timeline)

`SuperAdmin_Org_GetDetail` currently only returns the *last* rejection reason inline. The prototype's org drawer renders a full multi-entry timeline (`renderTimeline()` in the prototype JS) — every status transition with who changed it and why. Add a dedicated list endpoint instead of overloading `GetDetail`.

```sql
CREATE PROCEDURE SuperAdmin_Org_GetStatusHistory(IN p_OrgId INT UNSIGNED)
BEGIN
    SELECT
        h.OrgStatusHistoryId,
        oldv.ValueCode  AS OldStatus,
        oldv.ValueName  AS OldStatusName,
        newv.ValueCode  AS NewStatus,
        newv.ValueName  AS NewStatusName,
        h.Reason,
        h.ChangedByType,
        h.ChangedBy,
        h.CreatedAt
    FROM OrgStatusHistory h
    LEFT JOIN LookupValues oldv ON h.OldStatusLkpId = oldv.LookupValueId
    JOIN      LookupValues newv ON h.NewStatusLkpId = newv.LookupValueId
    WHERE h.OrgId = p_OrgId
    ORDER BY h.CreatedAt DESC;
END //
```

Add to `ISuperAdminDal`: `Task<ApiResponse<List<DynamicRow>>> GetOrgStatusHistoryAsync(int orgId);`
Add to `SuperAdminDal`: implementation via `ExecuteDynamicListAsync("SuperAdmin_Org_GetStatusHistory", ...)`.
Add to `SuperAdminController`: `GET /orgs/{orgId:int}/history`.

### Step 2 — New module: Member / User admin review (the prototype's Members screen currently has no backend at all)

The prototype's Members tab, searchable multi-select org filter, and member drawer (profile verification, account status, skills/interests/badges/impact, other-orgs, documents, suspend/reactivate) were all built against static `MEMBER_DATA` sample JSON — **none of it is wired to a real endpoint yet.** This is the single largest gap between the prototype and a working admin panel.

Three distinct status dimensions must stay separate — this was a deliberate design decision, do not collapse them:
- **Membership status** — per-org (`OrgMembers.StatusLkpId` or equivalent) — already exists, read-only here.
- **Account status** — global, maps to `Users.IsActive` — Super Admin can suspend/reactivate.
- **Profile verification status** — Super Admin's own document/profile check — new concept, needs its own lookup type `PROFILE_VERIFICATION_STATUS` (`PENDING`, `VERIFIED`, `NEEDS_UPDATE`) and a place to store it. Recommend a new column `Users.ProfileVerificationLkpId` (nullable, defaults to `PENDING`) rather than a new table, since it's a single current-state value per user, not an audit trail. If a history trail is wanted later, mirror the `OrgStatusHistory` pattern with a new `UserProfileVerificationHistory` table — not required for v1.

**New table (schema change, small):**
```sql
ALTER TABLE Users ADD COLUMN ProfileVerificationLkpId INT UNSIGNED NULL AFTER IsActive;
-- FK to LookupValues, new LookupType PROFILE_VERIFICATION_STATUS with values PENDING/VERIFIED/NEEDS_UPDATE
```
