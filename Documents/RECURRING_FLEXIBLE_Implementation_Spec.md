# RECURRING / FLEXIBLE Project Flow — Full Implementation Spec
**NGO Connect | Version: Pre-v5.1 | Date: 2026-08-13**
**Constraint: Existing project list cards, project edit form structure, and existing tab layouts remain unchanged. All changes are ADDITIONS only except for the SPs and DAL methods explicitly listed as "update".**

---

## 0. Vocabulary

| Term | Meaning |
|---|---|
| ONE_TIME | Single-day project, existing flow unchanged |
| RECURRING | Multi-session project on fixed days/time; sessions auto-generated by Hangfire |
| FLEXIBLE | Open date-range project; volunteer self-checks-in and checks-out |
| CLOSING | New project lifecycle status between ACTIVE and COMPLETED. Admin reviews, issues certs, enters final skill ratings |
| MinAttendPct | Per-project minimum attendance % for certificate eligibility |
| MaxDailyHours | FLEXIBLE: max hours a volunteer can log in one calendar day |
| MinSessionHours | FLEXIBLE: minimum check-in/checkout period duration to count toward total |
| EligibleSessions | RECURRING: sessions after the volunteer's approval date |

## 1. Database Schema Changes

### 1.1 New Columns on Existing Tables

#### `Projects` table — 3 new columns

```sql
ALTER TABLE Projects
  ADD COLUMN MinAttendPct    TINYINT UNSIGNED NULL AFTER MinHoursRequired,
  ADD COLUMN MaxDailyHours   DECIMAL(4,2)     NULL AFTER MinAttendPct,
  ADD COLUMN MinSessionHours DECIMAL(4,2)     NULL AFTER MaxDailyHours;
```

| Column | Type | Purpose | Who sets it |
|---|---|---|---|
| `MinAttendPct` | TINYINT UNSIGNED NULL | Cert threshold override for this project. NULL = use global Setting. Applies to both RECURRING (% of eligible sessions) and FLEXIBLE (% of total available hours). | Admin at creation (pre-filled from Settings) |
| `MaxDailyHours` | DECIMAL(4,2) NULL | FLEXIBLE only: maximum hours a volunteer can log in a single calendar day. NULL = use `FLEXIBLE_MAX_DAILY_HOURS` setting. | Admin at creation (pre-filled from Settings) |
| `MinSessionHours` | DECIMAL(4,2) NULL | FLEXIBLE only: minimum check-in→checkout duration (hours) for that period to count. Shorter periods are discarded. NULL = use `FLEXIBLE_MIN_SESSION_HOURS` setting. | Admin at creation (pre-filled from Settings) |

#### `UserBadges` table — no changes needed
The `SessionId` column is **not** added. Milestone thresholds no longer award badges — they send notifications. The only new badge is `PROJECT_COMPLETE` (awarded on cert issuance), which already works with the existing `UserBadges` schema (ProjectId context is sufficient).

### 1.2 New Table: `UserSessionSkillRatings`

```sql
CREATE TABLE UserSessionSkillRatings (
    SessionSkillRatingId INT UNSIGNED   NOT NULL AUTO_INCREMENT,
    UserId               INT UNSIGNED   NOT NULL,
    ProjectId            INT UNSIGNED   NOT NULL,
    SessionId            INT UNSIGNED   NOT NULL,
    SkillId              INT UNSIGNED   NOT NULL,  -- ProjectSkills.ProjectSkillId
    Rating               DECIMAL(3,2)  NOT NULL,   -- 1.0 – 5.0
    RatedBy              INT UNSIGNED   NOT NULL,
    Notes                TEXT           NULL,
    CreatedAt            DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UpdatedAt            DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (SessionSkillRatingId),
    UNIQUE KEY uq_session_skill_rating (UserId, ProjectId, SessionId, SkillId),
    INDEX idx_ssr_user    (UserId),
    INDEX idx_ssr_project (ProjectId),
    INDEX idx_ssr_session (SessionId),
    CONSTRAINT fk_ssr_user    FOREIGN KEY (UserId)    REFERENCES Users(UserId),
    CONSTRAINT fk_ssr_project FOREIGN KEY (ProjectId) REFERENCES Projects(ProjectId),
    CONSTRAINT fk_ssr_session FOREIGN KEY (SessionId) REFERENCES ProjectSessions(SessionId),
    CONSTRAINT fk_ssr_ratedby FOREIGN KEY (RatedBy)   REFERENCES Users(UserId)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

Purpose: store per-session skill ratings separately from the final project rating in `UserSkillRatings`. Admin can rate each skill after each RECURRING session. Final ratings in `UserSkillRatings` are entered at CLOSING.

#### LookupType: NOTIFICATION_TYPE — add 5 new types

#### `Certificate_Issue` — remove `p_TotalHours`, compute from DB
**Remove param:** `IN p_TotalHours DECIMAL(6,2)` — completely remove from SP and DAL.
**Add computation inside SP body:**
```sql
-- Compute TotalHours based on project schedule type
-- ONE_TIME / RECURRING: SUM(HoursLogged) from ATTENDED rows for this volunteer/project
-- FLEXIBLE: SUM of (CheckOutTime - CheckInTime) capped by MaxDailyHours per day
DECLARE v_TotalHours DECIMAL(6,2);
DECLARE v_ScheduleCode VARCHAR(20);
SELECT lv.ValueCode INTO v_ScheduleCode
FROM Projects p
JOIN LookupValues lv ON p.ScheduleTypeLkpId = lv.LookupValueId
WHERE p.ProjectId = p_ProjectId;

IF v_ScheduleCode = 'FLEXIBLE' THEN
    SELECT COALESCE(SUM(pa.HoursLogged), 0) INTO v_TotalHours
    FROM ProjectAttendance pa
    JOIN ProjectSessions ps ON pa.SessionId = ps.SessionId
    WHERE ps.ProjectId = p_ProjectId AND pa.UserId = p_UserId
      AND pa.AttendStatusLkpId = (SELECT LookupValueId FROM LookupValues WHERE ValueCode = 'ATTENDED' LIMIT 1);
ELSE
    SELECT COALESCE(SUM(pa.HoursLogged), 0) INTO v_TotalHours
    FROM ProjectAttendance pa
    JOIN ProjectSessions ps ON pa.SessionId = ps.SessionId
    WHERE ps.ProjectId = p_ProjectId AND pa.UserId = p_UserId
      AND pa.AttendStatusLkpId = (SELECT LookupValueId FROM LookupValues WHERE ValueCode = 'ATTENDED' LIMIT 1);
END IF;
```
**DAL change:** remove `p_TotalHours` from `AddWithValue` in `CertificateDal.IssueAsync`.
**Model change:** remove `TotalHours` from `IssueCertificateRequest`.

#### `UserBadge_Award` — add `p_SessionId` param

**Add to INSERT:** `SessionId = p_SessionId`

### 2.2 New SPs

#### `Project_FlexCheckIn`
```
IN p_ProjectId INT UNSIGNED
IN p_UserId    INT UNSIGNED
IN p_SessionId INT UNSIGNED   -- the FLEXIBLE project's active session for today
```
Validates (in order — returns descriptive error on each):
1. Project exists, ACTIVE, `IsDeleted = 0`
2. User has APPROVED application for this project
3. Today is within `FlexFromDate → FlexToDate`
4. Current server time is within the allowed check-in window:
   `CURTIME() BETWEEN SUBTIME(p.SessionStartTime, SEC_TO_TIME(v_BufferSecs)) AND p.SessionEndTime`
   where `v_BufferSecs = CHECKIN_BUFFER_MINUTES × 60` (read from Settings via `SettingsCache` equivalent — SP reads from Settings table).
5. No existing `CHECKED_IN` or `ATTENDED` record for this user on this session

Inserts `ProjectAttendance` row: `AttendStatusLkpId = CHECKED_IN`, `CheckInTime = NOW()`.
Returns: `IsSuccess`, `Message`, `AttendanceId`.

**Check-in window:** Opens `CHECKIN_BUFFER_MINUTES` minutes before `SessionStartTime`. Closes at `SessionEndTime`. A volunteer who arrives 15 minutes early can check in; one who tries at 11 PM when session ended at 5 PM cannot.

#### `Project_FlexCheckOut`
```
IN p_ProjectId    INT UNSIGNED
IN p_UserId       INT UNSIGNED
IN p_AttendanceId INT UNSIGNED
```
Reads the CHECKED_IN row, computes `duration = TIMESTAMPDIFF(MINUTE, CheckInTime, NOW()) / 60.0`.
Reads `MaxDailyHours` from `Projects` (fallback: Settings `FLEXIBLE_MAX_DAILY_HOURS`).
Reads `MinSessionHours` from `Projects` (fallback: Settings `FLEXIBLE_MIN_SESSION_HOURS`).
Sums today's already-logged hours for this user/project.
If duration < MinSessionHours → returns failure (period too short to count).
Cap: `min(duration, MaxDailyHours - todayAlreadyLogged)`.
Updates row: `CheckOutTime = NOW()`, `HoursLogged = cappedHours`, `AttendStatusLkpId = ATTENDED`.
Returns: `IsSuccess`, `Message`, `HoursLogged`.

#### `Project_GetVolunteerEligibility`
```
IN p_ProjectId INT UNSIGNED
IN p_UserId    INT UNSIGNED   -- NULL = return all volunteers for CLOSING screen
```
Returns per volunteer:
- `UserId`, `FullName`, `ProfilePhoto`
- `ScheduleTypeCode` (RECURRING / FLEXIBLE)
- RECURRING: `AttendedSessions`, `EligibleSessions`, `AttendPct`, `MinAttendPct`, `IsEligible`
- FLEXIBLE: `HoursLogged`, `AvailableHours`, `AttendPct`, `MinAttendPct`, `IsEligible`
- `CertCode` (NULL if not issued yet)

Formula for RECURRING eligible sessions:
```sql
-- Sessions with date >= volunteer's approval date AND project's SessionDate <= project end date
SELECT COUNT(*) FROM ProjectSessions ps
WHERE ps.ProjectId = p_ProjectId
  AND ps.SessionDate >= (SELECT DATE(StatusUpdatedAt) FROM ProjectApplications
                         WHERE ProjectId = p_ProjectId AND UserId = v.UserId AND StatusCode = 'APPROVED')
  AND ps.IsDeleted = 0;
```

Formula for FLEXIBLE available hours:
```sql
-- DATEDIFF(FlexToDate, FlexFromDate) × daily_session_hours
SELECT DATEDIFF(FlexToDate, FlexFromDate) *
       (TIMESTAMPDIFF(MINUTE, SessionStartTime, SessionEndTime) / 60.0)
FROM Projects WHERE ProjectId = p_ProjectId;
```

#### `Project_CheckMilestoneNotification`
```
IN p_ProjectId INT UNSIGNED
IN p_UserId    INT UNSIGNED
```
Called by Hangfire's `MilestoneNotificationJob` after each ATTENDED record is committed.

Logic:
1. Reads `MILESTONE_1_PCT` (25), `MILESTONE_2_PCT` (50), `MILESTONE_3_PCT` (75) from Settings.
2. Computes `currentPct`:
   - RECURRING: `ROUND(attendedSessions / eligibleSessions * 100)`
   - FLEXIBLE: `ROUND(hoursLogged / availableHours * 100)`
3. For each threshold [25, 50, 75] that `currentPct` has crossed:
   - Check `Notifications` table: if volunteer already has a `MILESTONE_XX` notification for this project → skip (prevents duplicate sends)
   - Otherwise: call `Notification_Create` with the milestone type and a project-specific body.
4. No badge rows created. No `UserBadges` writes.
5. Returns: `IsSuccess`, `NotificationsSent INT` (0–3).

Notification body per threshold (dynamic, uses project name):
```
MILESTONE_25: title="Great start! 🎯"
              body="You've completed 25% of [ProjectName]. Keep up the momentum!"
MILESTONE_50: title="Halfway there! 🌟"
              body="50% done on [ProjectName]. You're making a real difference!"
MILESTONE_75: title="Almost there! 🔥"
              body="75% of [ProjectName] complete. One final push — you've got this!"
```
`RefId = p_ProjectId`, `RefType = 'PROJECT'` — tapping the notification navigates to project detail.

**`PROJECT_COMPLETE` badge** is still awarded (to `UserBadges`) when `Certificate_Issue` succeeds — that stays in the cert issuance SP, not here.

## 4. Hangfire Background Jobs (all new)

| Job class | Cron setting key | Purpose |
|---|---|---|
| `GenerateRecurringSessionsJob` | `CRON_GENERATE_SESSIONS` | Daily: generates ProjectSessions rows for next N days for all ACTIVE RECURRING projects |
| `AutoActivateSessionsJob` | `CRON_AUTO_ACTIVATE` | Hourly: UPCOMING sessions whose date/time has arrived → set status ACTIVE |
| `AutoCompleteSessionsJob` | `CRON_AUTO_COMPLETE` | Hourly at :30: ACTIVE sessions whose EndTime has passed → set status COMPLETED |
| `AutoCheckoutMissedJob` | `CRON_AUTO_CHECKOUT` | Every 15 min: CHECKED_IN attendance records past (session EndTime + grace minutes) → auto CHECKOUT_MISSED, compute partial hours if ≥ MinSessionHours |
| `AutoTransitionToClosingJob` | `CRON_AUTO_CLOSING` | Daily: ACTIVE projects whose end date has passed → call Project_TransitionToClosing |

## 7. SP to update — `Application_GetByUser`

**ADD to SELECT for each application:**
```sql
-- Attendance progress (for ImpactScreen + MyProjectsScreen)
(SELECT COUNT(*) FROM ProjectAttendance pa
 JOIN ProjectSessions ps ON pa.SessionId = ps.SessionId
 WHERE ps.ProjectId = pa2.ProjectId AND pa.UserId = pa2.UserId
   AND pa.AttendStatusLkpId = (SELECT LookupValueId FROM LookupValues WHERE ValueCode = 'ATTENDED' LIMIT 1))
 AS MyAttendedSessions,

-- Eligible sessions for RECURRING (from approval date)
(SELECT COUNT(*) FROM ProjectSessions ps2
 WHERE ps2.ProjectId = pa2.ProjectId
   AND ps2.SessionDate >= DATE(pa2.StatusUpdatedAt)
   AND ps2.IsDeleted = 0)
 AS MyEligibleSessions,

-- Hours logged for FLEXIBLE
(SELECT COALESCE(SUM(pa2b.HoursLogged), 0) FROM ProjectAttendance pa2b
 JOIN ProjectSessions ps3 ON pa2b.SessionId = ps3.SessionId
 WHERE ps3.ProjectId = pa2.ProjectId AND pa2b.UserId = pa2.UserId
   AND pa2b.AttendStatusLkpId = (SELECT LookupValueId FROM LookupValues WHERE ValueCode = 'ATTENDED' LIMIT 1))
 AS MyHoursLogged,

p.MinAttendPct,
p.MaxDailyHours,
-- Active check-in
(SELECT pa3.AttendanceId FROM ProjectAttendance pa3
 JOIN ProjectSessions ps4 ON pa3.SessionId = ps4.SessionId
 WHERE ps4.ProjectId = pa2.ProjectId AND pa3.UserId = pa2.UserId
   AND pa3.AttendStatusLkpId = (SELECT LookupValueId FROM LookupValues WHERE ValueCode = 'CHECKED_IN' LIMIT 1)
 ORDER BY pa3.CreatedAt DESC LIMIT 1) AS ActiveCheckInId,

vc.CertCode AS MyCertCode
```
